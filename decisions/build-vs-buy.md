# 是否应该自己开发

## 默认答案

**先证明必须自研。**

Vibe Coding 很容易把“我需要一个能力”直接翻译成“我需要写一个新模块”。这一步必须被拆开。

## 决策顺序

1. 当前项目是否已经有这个能力？
2. 通过配置、组合现有模块或很小的扩展能否完成？
3. 是否存在成熟开源项目可直接部署或嵌入？
4. 是否存在成熟公共 API？
5. 是否存在成本可接受的 SaaS/PaaS？
6. 只有前面都不合适，才进入自研设计。

## 优先查询

- `awesome-selfhosted`：成熟自托管软件
- `public-apis`：现成 API
- `free-for-dev`：SaaS/PaaS/IaaS
- `awesome`：继续定位具体领域的成熟项目列表

来源定义见 `sources/trusted-sources.yaml`。

## 必须自研的常见理由

- 核心业务差异就是这项能力
- 数据/合规要求导致外部方案不可用
- 现有方案无法满足关键接口或性能要求
- 外部方案长期成本显著高于可控的自研成本
- 对关键行为需要完全控制，而现有方案无法扩展

## 不能单独成立的理由

- “自己写更灵活”
- “以后可能有更多需求”
- “AI 写起来很快”
- “第三方看起来麻烦”
- “我们可以顺便做得更好”

## 验证输出

最终必须写清：

- 候选现成方案
- 为什么不能直接复用
- 自研的长期维护责任
- 自研最小范围
- 如果判断错误，如何退出/替换

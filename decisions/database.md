# 数据库与数据存储

## 这张卡解决什么

帮助判断应该保持现有数据库、增加新存储类型、迁移数据库，还是改变数据模型。

**这张卡不预设关系型数据库优先，也不预设“已有数据库一定继续用”。**

## 建议检查的维度

- 数据模型：关系、文档、时序、图、向量、日志等
- 读写比例
- 查询模式
- 事务与一致性要求
- 延迟与吞吐目标
- 数据规模与增长方式
- 索引与查询能力
- 全文/向量/聚合需求
- 多租户、隔离和权限
- 高可用、备份与恢复
- 运维能力
- 数据迁移成本
- 双写/同步复杂度
- 云服务与自托管限制
- 成本

## 常见候选

- 保持当前数据库并调整 schema / index / query
- 使用当前数据库已有扩展能力
- 增加专用搜索/分析/向量/时序存储
- 迁移到另一种数据库
- 多存储组合
- 托管服务

没有固定顺序；具体场景可能一开始就适合专用存储。

## 研究来源

- 候选数据库官方文档
- `system-design-primer`
- `system-design`
- 与目标数据模式接近的成熟生产实现
- 实际 benchmark（测试条件必须匹配当前场景）

## 容易误导判断的说法

- “NoSQL 更适合大数据”
- “PostgreSQL 什么都能做，所以永远不用别的”
- “专用数据库一定比通用数据库快”
- “向量数据就必须独立 Vector DB”
- “以后数据很多，所以现在先拆”

这些都是可能成立但需要证据的命题。

## 自主判断要求

AI 应比较候选的实际 trade-off；如果当前数据模式天然更适合新存储，可以直接建议，不需要先完成一套形式化的“现有数据库优化流程”。

# 数据库怎么选

## 默认原则

**优先使用项目已经拥有的主数据库。**

不要因为新增一种查询模式就立即新增一种数据库。

## 关系型数据库优先的典型场景

- 业务数据存在明确关系
- 需要事务和一致性
- 需要复杂查询、聚合、约束
- 数据模型整体可预测

## 引入另一类数据库前必须证明

- 现有数据库经过合理 schema、索引、查询优化后仍不满足需求
- 新数据库解决的是明确瓶颈，而不是抽象的“扩展性”
- 团队能够承担备份、监控、升级、故障恢复和数据一致性成本
- 数据同步/双写问题已经有明确设计

## 选型流程

1. 定义数据访问模式和一致性要求。
2. 测量当前数据库瓶颈。
3. 优化 schema / index / query / pagination。
4. 再判断是否需要：
   - 搜索引擎
   - 时序数据库
   - 文档数据库
   - 向量数据库
   - 独立分析仓库
5. 查官方文档。
6. 用 `system-design-primer`、`system-design` 交叉验证 trade-off。
7. 查成熟真实项目实现。

## 禁止理由

- “NoSQL 更适合大数据”
- “PostgreSQL 性能不够”但没有测量
- “以后数据很多”
- “向量数据就必须独立 Vector DB”

## 输出必须包含

- 数据量和访问模式
- 一致性需求
- 当前瓶颈证据
- 保持现有数据库的方案
- 新数据库的额外运维成本
- 迁移与退出成本
